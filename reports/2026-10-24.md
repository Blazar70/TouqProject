## 3. Bugs (new)

**B8 — Medium — Doctor time off skips appointments marked "arrived"**
- When a manager saves time off, `save_doctor_time_off` moves the doctor's bookings to "Unassigned". It does this only for `status in ('requested', 'confirmed')` (`supabase/migrations/0058_doctor_time_off.sql:105`). The "will move N bookings" preview has the same list (`src/components/TimeOffPanel.tsx:64`). 0072 added `arrived` but did not update either one.
- Scenario: at 11:00 a doctor goes home sick. Three pets are already checked in as "arrived" for 11:30–12:30. The manager enters time off from 11:00. The preview says "0 bookings will move", and the three stay with the absent doctor. The guard trigger `enforce_doctor_not_away` only fires when the doctor or time *changes*, so nothing catches it. Push alerts now go only to an appointment's own doctor (`_shared/alertRecipients.ts:10`), so the other doctors are never told.
- Fix: a new migration that recreates the function with `status in ('requested', 'confirmed', 'arrived')`, plus the same change in `TimeOffPanel.tsx:64`. Add one line to the 0058 check script.

**B9 — Low — "Arrived" can be set on any future appointment, and a rescheduled one stays "arrived"**
- The check-in button shows for every active appointment, whatever its date (`AppointmentsPage.tsx:951`). It even shows on a still-unconfirmed request, which skips confirmation. "Not arrived yet" then sets it to `confirmed` rather than back to `requested` (`:957`).
- Scenario: a receptionist mis-taps "Arrived" on next Tuesday's card. That pet then shows as "waiting" all week, and doctors get an "X has arrived" push at once.
- Fix: show the button only when `clinicDay(appointment.scheduled_at) === clinicDay()`. On reschedule, set an `arrived` appointment back to `confirmed`.

**B10 — Low — Typing an Arabic digit into a selected number field adds it instead of replacing**
- `installArabicDigitInput` (`src/lib/arabicDigits.ts:24`) always writes `input.value + latin`. Number fields expose no cursor or selection, so the code cannot know that text was selected.
- Scenario: the quantity box holds "1". The receptionist selects it and types "٢" on an Arabic keyboard. The box now says "12", not "2", and the line total is 12× without anyone noticing. Latin keyboards replace the selection as normal.
- Fix: for the money and quantity boxes, use `type="text" inputMode="decimal"` and run `toLatinDigits` in `onChange`, as the original H6 suggested. Text fields have a real selection, so the global listener is no longer needed there.

**B11 — Low — A manager's backdated payment time uses the device's time zone**
- `PaidAtField` (`src/components/PaidAtField.tsx:5,16,30`) builds the `datetime-local` value from the device's clock. `PaymentsPage.tsx:326` sends it as `new Date(paidAt).toISOString()`, which also reads it as device time.
- Scenario: the owner enters a late payment from a laptop still set to UTC (for example while travelling). "20:00" is stored as 23:00 Riyadh time, and on a late evening it can land on the wrong cash-up day.
- Fix: convert with the existing `clinicTimeToIso(date, time)` helper (as `TimeOffPanel` does), and use `isoToClinicFields` to fill the field in.

## 4. Security (new)

**S8 — Medium — A cash count can be overwritten silently, and the box shows the expected amount**
- `cash_counts` keeps one row per branch and day: "the latest count is kept" (`0071_cash_counts.sql:5,15`). The panel saves with `upsert`, so a new save overwrites the old count (`CashCountPanel.tsx:47`). Nothing is written to `admin_audit_log`. Before anything is typed, the box shows the *expected* cash as a hint (`:100`).
- Scenario: at closing, the receptionist counts 1,450 SAR and saves. The screen shows −50.00 in red. They type 1,500 and save again. Now the difference is 0.00, "counted by" shows their name, and the 1,450 is gone. The manager reviewing that night sees a perfect day. The count was meant to catch a shortage, and it can be undone by the person it checks.
- Fix:
  - Make the table insert-only (`revoke update`). Show the latest count and "recounted N times" from the history.
  - Or log each change to `admin_audit_log` in `cash_counts_guard`, the way credit notes are logged.
  - Remove the expected amount from the placeholder (see H11).

**S9 — Low — Purging a single pet leaves its photos in storage**
- The clinic purge now removes files (S5 fixed). The pet purge does not:
  - "Purge now" (`PetsPage.tsx:139`) and the nightly cron (`0032_pet_staff_trash.sql:25`) only delete the `pets` row.
  - The pet's photo stays at `pet-photos/<clinic>/<pet>.<ext>` (`PetDetail.tsx:193`).
  - Its visit-record photos stay at `<clinic>/records/<recordId>.<ext>` (`SessionPage.tsx:205`).
- Scenario: an owner asks the clinic to delete their pet's data under PDPL (the Saudi personal-data law). After the purge, the rows are gone but the photos stay in the bucket for good, with nothing left that points to them.
- Fix: in `handlePurgePet`, remove `photo_url` and the records' photo paths from storage before deleting the row. For the cron, a small scheduled edge function (service role) can do the same, or the trash can be purged only through that function.

**S10 — Low — The clinic purge ignores storage errors**
- `removeFolder` in `admin-manage-clinic/index.ts:78,83` returns quietly on a list or remove error. `purgeClinic` then logs `clinic_purged` as if it all worked.
- Scenario: a storage timeout during the purge leaves the photos, and the admin log says "purged".
- Fix: collect the errors and return them, for example as "Clinic deleted; N files could not be removed". The order (rows first, then files) is right, so keep it.

### E) Hosting the PWA

What Touq needs:
- static files only (`npm run build` gives `dist/`), with an **SPA fallback**, because the app uses `createBrowserRouter`. A deep link such as `/appointments` must serve `index.html`.
- HTTPS, which service workers and web push require.
- the ability to set headers, so that `sw.js` is never cached long and a CSP can be added later (a CSP, Content Security Policy, is a header that limits which scripts may run).
- commercial use allowed.

| Host | Free plan (seen 2026-10-24) | Commercial use on free | Saudi edge | Effort | Risks |
|---|---|---|---|---|---|
| **Cloudflare Pages** (or Workers with static assets) | Static requests unlimited and free. 500 builds/month, 1 at a time. Paid Workers plan from $5/month (Cloudflare docs, snippet) | Not stated in the snippets **(unverified; check the ToS)** | Data centres in **Riyadh** (official 2018 blog), and in Jeddah and Dammam (third-party lists, **unverified**) | **S**: connect the repo, build `npm run build`, output `dist`. Add `public/_headers` for `sw.js` | Cloudflare is moving new projects from Pages to Workers static assets, so the setup may change, but the files stay plain |
| Vercel | Hobby: generous builds and bandwidth | **No**: Hobby is non-commercial. Pro needed (about $20/user/month, **unverified**) | No Saudi edge found | S | Not allowed for a paying clinic on the free plan |
| Netlify | Free: 300 credits/month (credit model) | Yes (third-party source) | No Saudi edge found | S | The credit model makes costs harder to predict |

Notes:
- Static hosting is the cheap, easy part. Touq is 422 KB of precached files, and no host's limits matter at that size.
- Whichever host you choose, add these before going live:
  - `/* /index.html 200` (Netlify/Cloudflare `_redirects`), or rely on Cloudflare Pages' automatic SPA mode, which is used when there is no `404.html`.
  - `Cache-Control: no-cache` on `/sw.js` and `/index.html`, so clinics get updates.
  - Later, a CSP header that allows only your Supabase URL.
- Sources: https://blog.cloudflare.com/riyadh · https://getdeploying.com/datacenters-in-saudi-arabia · https://developers.cloudflare.com/pages/functions/pricing/ · https://developers.cloudflare.com/workers/platform/pricing/ · https://dev.to/libme/vercel-vs-netlify-vs-cloudflare-pages-where-your-side-project-should-actually-live-1j30 · https://temps.sh/blog/cloudflare-pages-free-tier-limits-2026

### F) Database location and backups (Supabase)

The data question matters more than hosting. Owner names, phones and medical notes are personal data under the PDPL. The 10-23 report noted SDAIA's **draft amendment** (consultation until 5 Nov 2026), which proposes keeping personal data inside the Kingdom.

**Regions.** The official Supabase region list (search snippet of supabase.com/docs/guides/platform/regions) has **no Middle East region**. The nearest are Mumbai (`ap-south-1`) and Frankfurt (`eu-central-1`). No announcement of a Gulf region was found.

**AWS Saudi region.** Saudi Press Agency and others (Sep 2026) report that AWS's first Saudi region is "on track for **December 2026**", with 3 Availability Zones (an Availability Zone is a separate data centre in the same region). Supabase runs on AWS, but a new AWS region does **not** mean Supabase will offer it. Ask Supabase sales directly.

**Backups on Supabase** (official pricing page via search snippet, plus third-party guides from 2026):

| Plan | Price | Automatic backups | Point-in-time recovery (PITR) |
|---|---|---|---|
| Free | $0 | **None** | No |
| Pro | about $25/month per organization, with a $10 compute credit **(unverified)** | Daily, kept 7 days | Add-on: **$100/month per 7 days** of history |
| Team | about $599/month **(unverified)** | 14 days | Add-on |

PITR (point-in-time recovery) lets you rewind the database to any minute, not only to last night's copy.

Important limits:
- Supabase's backups cover **the database only, not Storage files** (pet photos, logos, billing PDFs).
- Free projects also pause after a period of no activity (**unverified** on the live page). That is fine for development, but not for a clinic.

**Do-it-yourself off-site backup** (a pattern from several 2026 guides):
- A scheduled GitHub Action runs `pg_dump --format=custom` against the **session pooler (port 5432)**. The transaction pooler on port 6543 does not work with `pg_dump`.
- Keep the database URL in GitHub Secrets.
- Write the file to disk, check its size, encrypt it (for example `age` or `gpg`), then upload it to storage you control.
- Don't pipe `pg_dump` straight to the upload: a failed dump can upload a cut-off file without anyone noticing.
- Keep the copy in a private bucket with lifecycle rules, not in a git repo: it is personal data.
- Copy the storage buckets separately (the Supabase CLI or an S3-compatible copy).
- Effort: **S–M**, one workflow file plus `scripts/backup.md`. This fits the repo's `scripts/` folder for admin tools.

**Self-hosting Supabase in KSA** (the fallback if in-Kingdom storage becomes law):
- Supabase is open source. It can run with Docker, or with Pigsty on top of a managed Postgres, on a Saudi cloud. Google Cloud Dammam is one option; the AWS Riyadh region from Dec 2026 is another. Saudi provider details were not researched tonight.
- Effort: **L**. You become responsible for upgrades, auth, storage, high availability and backups (Supabase's own self-hosting guide says so).
- Touq is already well placed for a move, because all logic lives in numbered SQL migrations and Deno functions.

Sources: https://supabase.com/docs/guides/platform/regions · https://supabase.com/pricing · https://www.jetadmin.io/blog/supabase-pricing-2026-guide-to-plans-limits-and-real-world-costs/ · https://makerkit.dev/blog/saas/supabase-pricing · https://www.spa.gov.sa/en/w2665748 · https://english.aawsat.com/technology/5313287-aws-launch-first-cloud-infrastructure-region-saudi-arabia-december · https://simplebackups.com/blog/backup-supabase-postgres · https://sia.hackernoon.com/i-didnt-want-to-pay-for-supabase-backups-so-i-built-my-own · https://pigsty.io/docs/app/supabase/

**Recommendation (F):**
1. **For a pilot:** use Supabase **Pro** in **Frankfurt** (`eu-central-1`, which also matches the Sentry EU advice from 10-23). Skip PITR at first; daily backups plus your own encrypted nightly `pg_dump` and storage copy are enough for a small clinic. **Do one test restore** into a scratch project before go-live. A backup you have never restored is a guess.
2. **Get the clinic's agreement in writing:** they consent to data being processed outside KSA. Note which processors are involved: Supabase/AWS EU, Cloudflare, and the push services (Google and Apple).
3. **Watch two dates:** the end of the SDAIA consultation on 5 Nov 2026, and the AWS Riyadh region in Dec 2026. If in-Kingdom storage becomes law, ask Supabase whether they will offer the Riyadh region. Otherwise plan a self-hosted move (L).
