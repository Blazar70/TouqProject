## 3. Bugs (new)

**B37 — Low — Crash reports are silently blocked if the Sentry project is not in the EU (Frankfurt) region**
- Where: `public/_headers:9`, `connect-src … https://*.ingest.de.sentry.io`.
- Scenario: the CSP (Content-Security-Policy, the browser rule list saying which servers the page may talk to) only allows Sentry's **German** ingest servers. A Sentry project created in the US region has a DSN (the address crash reports go to) like `o123.ingest.us.sentry.io`. The browser would then block every crash report with only a console message. Nobody notices, because Sentry is quiet when it receives nothing. The j20 sweep can't catch this: it checks that screens load, and Sentry only sends when something breaks. The 10-23 report recommended the EU region, so this is fine **if** staging's DSN contains `.ingest.de.`.
- Fix (S): check the `VITE_SENTRY_DSN` build variable in Cloudflare contains `ingest.de.sentry.io`. Add one line to `j20` that calls `Sentry.captureMessage('csp-check')` and fails on a CSP violation event, so a later region or DSN change is caught.

## 6. HCI / visual / usability ideas

**H58 — Microchip box: numeric keyboard on tablets** (S)
- Problem: the microchip input (`RegisterPetPage.tsx:199`, same in `PetDetail.tsx`) has no `inputMode`, so iPads and Android tablets open the full letter keyboard, often in Arabic. Typing 15 digits by hand is the common case when there is no scanner. `cleanMicrochip` already converts Arabic digits, so this is about speed.
- Who: receptionists registering pets, nurses at check-in.
- Change: add `inputMode="numeric"`. The rare 10-character AVID chips (with A–F letters, allowed by `MICROCHIP_PATTERN`) can still be typed by switching keyboards. Also add `enterKeyHint="next"`.

**H59 — Date of birth: allow "about 3 years old"** (S–M)
- Problem: the only way to give a pet's age is a full date picker (`RegisterPetPage.tsx:212`, `PetDetail.tsx`). Owners usually say "about two years" or "6 months". The receptionist then either skips it (so the weight chart's age line and age-based reminders get nothing) or invents a date that later looks exact.
- Who: receptionists; doctors reading the file later.
- Change: next to the date, two small number boxes "Age: [ ] years [ ] months". Filling them sets `date_of_birth` to today minus that age, and shows "(estimated)". Storing an `dob_estimated boolean` lets prints say "~2 y". Where: `RegisterPetPage.tsx`, `PetDetail.tsx`, a tiny helper next to `WeightChart`'s age maths.

**H60 — "Saved, but photo failed" should say what to do next** (S, pairs with B36)
- Problem: when a visit saves but its photo upload fails, the user sees only "Could not save photo" (`SessionPage.tsx:246-255`) and the photo is cleared. They don't know the visit itself **was** saved, so some re-enter the whole visit and create a duplicate.
- Who: doctors and nurses.
- Change: one message, "Visit saved. The photo was not saved: <reason>. Add it again from the visit." with the reason from `uploadPhoto` (too large / not supported / network), and keep the chosen file so a "Try again" button can retry the upload only.

### Y) Dependency updates and supply-chain protection

Background in plain words: Touq has 8 runtime and 14 dev packages, which pull in hundreds of others. Two risks: (1) **known bugs** in old versions (what `npm audit` lists), and (2) **poisoned new versions**. In 2025–2026 the "Shai-Hulud" worm campaigns published malicious versions of popular npm packages that steal tokens on install. Most were pulled within hours or days, so **waiting a few days before taking a new version** blocks most of them.

| Option | What it does | Price (seen 2026-11-03) | Fit for Touq | Effort | Risk / lock-in |
|---|---|---|---|---|---|
| **Dependabot** (built into GitHub) | Opens PRs to update packages and GitHub Actions. Security updates for audit findings; `groups` puts many bumps into one PR; **`cooldown: default-days: N`** waits N days (1–90) after a release before proposing it | Free | Best fit: Touq is GitHub-only, and CI (`checks.yml`) already runs types, lint, tests, build and migrations on every PR. One file: `.github/dependabot.yml` with `npm` + `github-actions`, weekly, grouped, `cooldown: default-days: 7` | **S** | Cooldown applies to version updates, **not** security updates (those come at once, which is what you want). Noise if not grouped |
| **Renovate** (Mend, free GitHub app) | Same idea, far more options; `minimumReleaseAge` per package type; auto-merge rules | Free for public/private repos | More power than Touq needs; config takes longer to learn | S–M | Third-party app with write access to the repo |
| **npm's own `min-release-age`** (npm ≥ 11.10, Feb 2026) | `npm install` refuses versions younger than N days | Free | Protects the developer PC and CI installs, not only bot PRs. **This machine has npm 10.9.9**, which silently ignores the setting, so it needs npm 11.10+ (also in CI) | S | Only works if every machine runs a new enough npm. pnpm 11 has this on by default (1 day) |
| **Socket.dev** (GitHub app) | Reads what a new package version actually does (install scripts, network calls, reading env vars) and comments on the PR or blocks it | Free tier (small team, reported ~3 members, 1,000 scans/month, malware blocking); Team $25/dev/month | Good second line once real clinic data exists; overkill for v1–v2 | S | Aggregator sources disagree on free-tier limits; check socket.dev/pricing |
| **GitHub "dependency review" action** | In CI, fails a PR that **adds** a package with a known high-severity issue | Free for public repos | Cheap extra gate; one step in `checks.yml` | S | Only knows *known* issues, not fresh malware |

Notes for Touq:
- Keep `npm ci` (it installs exactly what `package-lock.json` says) in CI, as now. Never run `npm install` in CI.
- Several packages use `^` ranges (`^2.110.3` etc.). That is fine with a lockfile plus Dependabot, but **do** let Dependabot also update `github-actions`: actions pinned to a tag (`@v4`) can be moved by their owner.
- Edge functions import `npm:@supabase/supabase-js@2` (any 2.x, fetched at deploy). Pinning an exact version (`@2.110.3`) there removes a supply-chain path that the lockfile doesn't cover.

**Recommendation (Y):** now: `npm audit fix`, add `.github/dependabot.yml` (npm + github-actions, weekly, grouped, `cooldown: default-days: 7`), and pin the edge-function import version. At v3 (real clinics): add Socket's free app and upgrade to npm 11.10+ with `min-release-age=7` in `.npmrc`. Skip Renovate.

### Z) MEWA vet-record rules (Arabic search, follow-up to X)
