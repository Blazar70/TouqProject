## 3. Bugs (new)

**B24 — High — The idle sign-out also turns off push alerts on that device**
- Where: `IdleLogout.tsx:39,54` calls `signOutThisDevice()` (`push.ts:74-80`). That function deletes the device's row in `push_subscriptions` and unsubscribes from push. It was written for the manual "Sign out" button on a shared device.
- Scenario: a doctor turns on notifications on their phone or the clinic tablet, then sees patients for 10 minutes without touching the screen. Touq signs out and removes the subscription. When reception checks in the next pet, `notify-status-change` finds no subscription for the doctor, so nothing arrives. Nobody is told, and the Settings toggle shows "off" only after they sign in again. Alerts only matter on a device nobody is touching, so in practice push now only works while someone is actively using the device. This also undoes last night's H31 (dashboard reload every 2 minutes for tablets left on all day): that tablet now signs itself out after 10 minutes. The background reloads don't count as activity.
- Fix (S): for idle, call `supabase.auth.signOut({ scope: 'local' })` and keep the push subscription. Unsubscribe only on a manual sign-out. If pet names on a lock screen worry you, make the push text generic while signed out. Better (M): an idle *lock* screen (re-enter the password, and the page stays as it was), plus a per-device "front-desk tablet" setting that is exempt or uses a longer limit.

**B25 — Medium — The idle sign-out throws away a visit record being written**
- Where: `IdleLogout.tsx:54` signs out with no check for unsaved changes. The app already tracks dirty forms (`useUnsavedChangesWarning.ts`, used by `SessionPage.tsx` and `PetDetail.tsx`), but `IdleLogout` ignores that. Signing out unmounts the page.
- Scenario: a doctor fills in the complaint, exam and half the prescription, then goes to take an X-ray or hold the animal for 11 minutes. The one-minute warning shows to an empty room, Touq signs out, and the typed record is gone. Rewriting clinical notes from memory is the kind of data loss users don't forgive.
- Fix (S): when a form is dirty, save it to `sessionStorage` before signing out and offer "Restore unsaved record" after sign-in, or simply skip the sign-out on a dirty form. The lock screen in B24 fixes both at once.

**B26 — Medium — The admin import accepts garbled Arabic and duplicates pets on a re-run**
- Garbled text: `AdminImportModal.tsx:24` reads the file with `file.text()`, which always decodes as UTF-8. Excel on Arabic Windows saves a plain "CSV (Comma delimited)" file in Windows-1256. Every Arabic letter then becomes `�` (the "unknown character" sign), and `buildImport` (`csvImport.ts`) doesn't check for it. The hint asks for "CSV UTF-8", but nothing enforces it. The result is 5,000 owner and pet names like `���� ������`, all committed, with no bulk undo.
- Duplicates: `0097_admin_import.sql:67` always inserts a new pet. Owners are matched by phone, but pets are not. If the network drops after the database commits (the button shows an error and the admin retries), or the admin imports a corrected file a second time, every pet now exists twice under the same owner, each with its own pet number.
- Fix (S): in `buildImport`, refuse any file containing `�` with "Save as CSV UTF-8". Optionally try `new TextDecoder('windows-1256')` as a fallback. Show the first 5 rows in the preview (H37). In the SQL, skip a pet when the same owner already has a pet with the same `lower(btrim(name))` and species, and count it as "already there".

**B27 — Low — Prescriptions show as one run-on line on screen**
- Where: `prescriptionText` joins lines with `\n` (`clinicalFields.ts`). The print keeps the line breaks (`.print-field-value { white-space: pre-wrap }`), but on screen the value sits in a plain `<div>` (`PetDetail.tsx:533-536`) or `<p>` (`AppointmentsPage.tsx:899-901`), which turns line breaks into spaces.
- Scenario: "Amoxicillin · 250 mg · twice a day · 7 days Meloxicam · 0.1 mg/kg · once a day". The duration of one drug runs into the name of the next, so a colleague reading the history can misread which dose belongs to which medicine.
- Fix (S): add `style={{ whiteSpace: 'pre-line' }}` (or a class) to those two value elements.

## 4. Security (new)

What I checked and found sound:
- **0096 prescriptions:** the trigger blocks a nurse from adding or changing `prescription`, on insert and on update. The app also drops it for nurses (`DOCTOR_ONLY_FIELDS`). The table check caps a prescription at 30 lines. `visit_templates` RLS (row-level security): clinicians of the same clinic can read, doctors and managers can write, and the admin can do everything. (Small point: `created_by` defaults to `auth.uid()` but a client could set it to anyone. It is only display data.)
- **0097 import:** `security definer` with `search_path` set. Only the admin may run it (checked inside the function). Execute is revoked from `anon`. Every row is checked again on the server (required fields, Saudi mobile pattern). It runs in one transaction. Owner contact fields are synced by the existing 0063 trigger.
- **Edge functions:** `reset_mfa` in `admin-manage-clinic` is reachable only by a verified admin (the cron caller is refused), and it is logged. `jwtAal` reads the token only after `getUser()` has verified it. MFA is off (`MFA_ENFORCED = false`), so nothing changes today.
- **Sentry (`sentry.ts`):** no user info, cookies, headers or bodies are sent, and query strings are cut from URLs and breadcrumbs. Only user and clinic IDs go out. It is loaded only when `VITE_SENTRY_DSN` is set. One gap: error *messages* can still contain data. For example, a Postgres error such as `duplicate key … (phone)=(+9665…)` sent to Sentry would include the phone number. Low. Add a `beforeSend` scrub of `+966` digit runs if you want to be strict.
- **Repo is public** (`.gitignore` comment): `HANDOFF.md` and `.env.sweep.local` are ignored, and no `.env` or handoff file is tracked (checked `git ls-files`).

**S18 — Medium (deadline 30 Oct 2026) — Supabase stops giving new tables to the app automatically**
- What changes: according to Supabase's changelog entry "Breaking change: tables not exposed to Data and GraphQL API automatically" (#45329) and several write-ups, tables created in `public` from 30 Oct no longer get the automatic `select/insert/update/delete` grants for `anon` and `authenticated`. Brand-new projects have worked this way since around 30 May. Sources disagree on whether existing projects change tomorrow or only new tables in new projects, so treat it as applying everywhere.
- Why it hits Touq: live is still at 0046. The go-live plan (`docs/v2-reset-plan.md`, decision 1) applies 0047–0097 to it, and those migrations create **22 tables** (`owner_files`, `invoice_payments`, `inpatient_stays`, `pet_waivers`, `visit_templates`, …). None of them has a table-level `grant … to authenticated`. They relied on the old automatic grant (the few grants they do have are column-level, e.g. `0063:77`). After the change those screens fail with `permission denied for table …` (error 42501). The same applies to "Option B" (a new project plus `rebuild-db.mjs`) and to every future migration.
- Fix (S–M): add explicit grants per table to the migrations, or as one new migration that lists each app table, matching what staging has today. Read the current grants with `select grantee, table_name, privilege_type from information_schema.role_table_grants where table_schema='public'` on staging. Don't use `grant all on all tables in schema public`: it would undo deliberate revokes like `0061:138` on `invoices`. Test by applying the full chain to a throwaway project.

**S19 — Medium — The backup drill can't restore a working Touq**
- Where: `scripts/backup-drill.sh:19,30` (`--no-privileges -n public`).
- (1) `--no-privileges` drops every GRANT and REVOKE. A restored copy loses the `0061` revoke on invoices and the column-level grants (0063, 0081, 0084, 0087). Depending on S18, the app then gets "permission denied" everywhere, or clients get back write rights you deliberately removed.
- (2) `-n public` leaves out `auth.users`, but `profiles.id references auth.users` (`0001_init.sql:25`). When `pg_restore` adds that foreign key to an empty project, the check fails, and with `--exit-on-error` the restore stops. In practice the drill would report failure, not success.
- (3) Storage files (pet photos, payment documents, logos, inpatient media) are not in the dump. The "row counts match" check can't notice that.
- Fix (S): drop `--no-privileges`. Dump `auth.users`/`auth.identities` too (data only), or restore the auth rows first. Note in the script that buckets need a separate copy (e.g. `supabase storage cp`, or a small Node script through the Storage API). Rows can match while photos are missing.

## 6. HCI / visual / usability ideas

**H34 — A printed prescription for the owner** (S–M)
- Problem: prescriptions are only printed inside the full pet summary, together with the history. Saudi clinics hand owners a one-page prescription to take home or to a pharmacy.
- Who: doctors finishing a visit, owners.
- Change: a "Print prescription" button next to the editor in `SessionPage.tsx`, and on each record in `PetDetail.tsx`. Reuse `buildDocument` in `PrintContext.tsx` with the clinic header, pet, owner, date, doctor name, a table of lines (medicine / dose / how often / how long / note), bilingual labels via `bi()`, and an A5 or 80 mm size via `printSize.ts`.

**H35 — Make the prescription editor faster on a tablet** (M)
- Problem: each line has 5 free-text boxes (`PrescriptionEditor.tsx`). Typing "every 12 hours" and "7 days" again and again on a touch keyboard, switching between Arabic and English, is slow. Different spellings also make records harder to read.
- Change: under "how often" and "how long", add tap chips (`q24h / q12h / q8h`, `3 / 5 / 7 / 14 days`) that fill the box in the current language. Add "Repeat last prescription" (copy from the pet's previous record). Keep free text. Templates (0096) already cover the common cases, so start with the chips.

**H36 — The weight chart has no scale** (S)
- Problem: `WeightChart.tsx` shows a line and the first and last dates, but no kg values on the axis. The values sit in `<title>` tooltips, which never appear on a touch screen. A doctor can't see at a glance whether the swing is 0.2 kg or 4 kg without opening "Show all".
- Change: print the min and max kg at the left of the plot (inside the `dir="ltr"` row), and tint the last point red when it changed more than 10% since the previous point.

**H37 — Show sample rows in the import preview** (S, goes with B26)
- Problem: the preview (`AdminImportModal.tsx`) only says "N pets, M owners". The admin can't see garbled Arabic, swapped columns (pet name in the owner column), or day/month mix-ups in dates before committing up to 5,000 rows.
- Change: render the first 5 cleaned rows as a small table, with dates shown as `formatDate` (e.g. "1 Mar 2022"), so a misread `03/01` is obvious.

**H38 — Let the idle warning be answered from across the room** (S, with B24)
- Problem: the warning is a small dialog with a 60-second countdown (`IdleLogout.tsx`), and it can't be seen from the exam table.
- Change: with the lock-screen approach from B24, the warning matters much less. Until then, show it as a full-width bar with large text, and play one short sound (`Audio`) if the device allows it.
