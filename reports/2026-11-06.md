## 3. Bugs (new)

**B44: Low (data loss): Finish throws away a visit photo whose upload failed**
- Where: `src/pages/SessionPage.tsx:303-320` (`handleFinish`) together with `saveRecord` at `:259-271`.
- Scenario: on clinic Wi-Fi the doctor adds an X-ray photo and presses **Finish**. The record saves, the photo upload fails, and `saveRecord` shows the toast "photo not saved" but still returns the record. `handleFinish` then sets the visit to `completed`, `setDone(true)` turns off the unsaved-changes guard, and the page moves to `/appointments`. The picked photo existed only in browser memory, so it's gone. The 11-04 fix (H60) keeps the photo for **Save** and autosave but not for **Finish**.
- Fix (S): after `saveRecord(true)`, if the photo is still pending (`photoFile` still set, or have `saveRecord` return a flag), stop and show "Photo not uploaded. Try again or remove it" before marking the visit completed.

**B45: Low: picking from the diagnosis list replaces the diagnosis text already typed**
- Where: `src/pages/SessionPage.tsx:454` `<DiagnosisPicker onPick={(name) => setField('diagnosis', name)} />` and `src/components/DiagnosisPicker.tsx:25-27`.
- Scenario: the doctor types "Otitis externa, left ear, yeast on cytology", then picks "Otitis" from the list to make the report count it. The whole text becomes "Otitis" with no undo, and autosave stores it 5 seconds later. Also, the database only links the visit to a term when the text matches **exactly** (`0106:51`), so a doctor who keeps detail in the field loses the count anyway.
- Fix (S): if the field isn't empty, ask before replacing, or append (`name + ' · ' + old`). Long-term, store the picked `diagnosis_term_id` as its own field rather than matching on the text (see H71).

**B46: Low: admin activity "Load older" can skip entries that share a timestamp**
- Where: `src/pages/AdminActivityPage.tsx:28-31` (`order('created_at')` + `.lt('created_at', before)`).
- Scenario: the new nightly auto-close job (`0107:24-27`) writes **one activity row per clinic in one statement**, so every row gets the same `created_at` (`now()` is fixed within a transaction). If the 200-row page boundary falls inside that group, "Load older" asks for rows *strictly older* than the last one shown, and the rest of the group never appears. That's the same "silently missing" problem H69 meant to solve. This also applies to any bulk action that logs several rows at once.
- Fix (S): order by `created_at desc, id desc` and page with `.or('created_at.lt.X,and(created_at.eq.X,id.lt.Y)')`.

**B47: Low (tablets): the pet-alert chip on Dashboard rows can't be read by touch**
- Where: `src/components/PetAlerts.tsx:26-33`, used at `DashboardPage.tsx:320,352`; CSS `App.css:5477`.
- Scenario: the pet's alert ("bites, muzzle") shows on the Dashboard only as a 14 px red triangle whose text sits in `title=` (a mouse-hover tooltip). On the reception iPad, hovering isn't possible, so the receptionist sees "some alert" but not what it is, right when the owner hands over the pet. Screen readers are fine (`aria-label`).
- Fix (S): show the first ~30 characters next to the icon (`<bdi>` + ellipsis), or make the chip a 44 px button that opens the full line.

## 7. Service research

Today's topic: **(AE) taking card payments in the clinic: card machines, "tap on phone" and how Touq should connect to them.** Topic C covered *online* gateways (owners paying by link); this covers the counter. Searched 2026-11-06. `geidea.net` and `docs.nearpay.io` couldn't be fetched (not in this session's allowed network list), so vendor details come from search results and press. **Prices aren't published by any of them; get quotes.**

Background in plain words: almost every Saudi clinic already has a **bank card machine** (a POS terminal from Al Rajhi, SNB, Geidea, etc.). Touq doesn't charge cards itself. The receptionist types the amount into the machine, then records "card" in Touq. Two upgrades exist: **(1) linking** the machine to the software (an "ECR" link: electronic cash register), so the amount is sent to the machine and the result comes back automatically; **(2) SoftPOS / tap on phone**: an NFC phone or tablet *becomes* the card machine.

|---|---|---|---|---|---|

| **Geidea terminals with ECR link** | SAMA-licensed Saudi acquirer (first non-bank to get an acquiring licence). Has terminals, a Direct API, and ECR mode on terminals; Odoo connectors use "Geidea Web ECR" | "Custom pricing" (directory listing) | Strong, local | **M–L**: ECR is usually a local Windows service or LAN link, awkward for a browser PWA | Ties the clinic to one acquirer; protocol docs need a sales contact |

Why it matters for Touq specifically: the money flow (invoices, VAT, cash-up, credit notes) is already strong, and the weak link is matching the **card machine total** with Touq's cash-up. A full terminal link adds a bank contract, a native app or local service, and certification, and a browser PWA (an installable web app) can't talk to NFC card hardware directly. The approval code gets most of the reconciliation value for almost no code.

**Recommendation (AE):** **now (v2): H72**, an optional approval-code field on card/Apple Pay payments, shown in cash-up. **v3:** don't build a terminal link. If a partner clinic asks, pilot **Geidea SoftPOS on an Android tablet** handed off from Touq with the amount (no card data passes through Touq), and keep a manual fallback. Re-check Tap to Pay on iPhone availability (SAMA/Geidea news) before v3, since most clinic tablets are iPads.
