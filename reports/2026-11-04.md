## 3. Bugs (new)

**B38 — Low (Medium once clinics use it on flaky Wi-Fi) — If the profile request fails at startup, the app opens with no role instead of showing an error**
- Where: `src/lib/AuthContext.tsx:93-97`. The `profiles` query result's `error` is never read. Only `data` is used, and `data` is `null` both for "this login has no profile" and for "the network dropped".
- Scenario: a receptionist opens the installed app on the clinic tablet while the Wi-Fi is reconnecting (the case migration 0102 was written for). The saved login is fine, but the profile request fails. `profile` becomes `null`, so `App.tsx` skips every check and renders the normal shell. The Dashboard shows only "Welcome to Touq." (`DashboardPage.tsx:192`). Payments, Reports and Reminders are hidden because `handlesMoney` is false. An **admin** gets the clinic-staff menu instead of the admin one. Nothing says "error", and nothing retries, so the user thinks their account lost its rights. Only a full reload fixes it. No data is exposed (the database still checks every request), so this is a usability bug, not a leak.
- Fix (S): keep the error: `const { data, error } = …`; if `error`, set a new `profileError` state and have `App.tsx` show a small "Couldn't load your account. [Try again]" screen that calls `refreshClinicName()`. See H61 for the wording.

**B39 — Low — A doctor's "upcoming appointments" on the Staff page go empty once they have about 1,000 appointments in total**
- Where: `src/components/StaffAppointments.tsx:25-29`. The query asks for **all** of a doctor's appointments, oldest first, with no limit and no date filter. Supabase's API returns at most 1,000 rows per request by default (the "max rows" setting).
- Scenario: a busy doctor sees about 20 patients a day. After about 2½ months they pass 1,000 appointments. The 1,000 rows returned are the oldest ones, which are all completed or cancelled. The newest ones, including every upcoming booking, are cut off. The manager opens Staff → that doctor and reads "No appointments assigned", while the doctor is fully booked. It also downloads every past row each time someone expands a staff member.
- Fix (S): two queries. Upcoming: `.gte('scheduled_at', startOfToday).not('status','in','(completed,cancelled)').order('scheduled_at').limit(50)`. Past: `.lt(...)` newest first, `.limit(50)`, loaded only when "Show past" is pressed.

**B40 — Low — Deleting a billing record removes its PDF first; if the delete then fails, the record stays but its PDF is gone**
- Where: `src/pages/AdminBillingPage.tsx:149-156`. The storage file is removed, **then** the `payments` row is deleted. The storage result isn't checked either.
- Scenario: the admin deletes a payment record while the connection drops, or the database refuses the delete. The toast shows the error and the row is still in the list, but its attached invoice PDF has already been deleted. "View document" now fails with "Object not found". That PDF is the only copy of what the clinic was billed.
- Fix (S): swap the order. Delete the row first, and only then remove the file (a leftover file is harmless, a lost one isn't).

## 6. HCI / visual / usability ideas

**H61 — A clear "couldn't load your account" screen with a Try again button** (S, pairs with B38)
- Problem: when startup loading fails, staff see an empty app with no explanation (B38).
- Who: everyone, most often reception on the shared tablet first thing in the morning.
- Change: a centred card like the "account disabled" screens (`App.tsx:53-65`): "Couldn't load your account. Check the internet connection." / "تعذّر تحميل حسابك. تحقّق من الاتصال بالإنترنت." with **Try again** (primary) and **Sign out** (secondary). Also retry once by itself when the browser fires `online`, since `OfflineBanner` already listens for that.

**H62 — Voice dictation for visit notes** (S for the free version, M for the cloud one; see research AA)
- Problem: doctors type the complaint, exam findings and plan (`SessionPage.tsx:398-447`) on a tablet, often with gloves on or while holding the animal. Typing Arabic medical notes on a touch keyboard is slow, so notes stay short.
- Who: doctors and nurses during and right after a visit.
- Change (free, now): add a short tip in the Session screen ("Tip: tap the 🎤 on your keyboard to dictate"). iPadOS and Android keyboards already dictate Arabic and English into any text box at no cost. Later (v3): a 🎤 button next to each notes box that records, sends the audio to an edge function, and inserts the text. See AA for the providers.

**H63 — Staff page appointments: show "today" and "next 7 days" first, with times only** (S, pairs with B39)
- Problem: the list mixes every upcoming booking, including old ones still marked "requested" or "confirmed" that nobody closed, in one long column with full dates.
- Who: managers planning cover for a doctor who is off.
- Change: group as "Today / This week / Later", show past-but-never-closed items in a separate amber group "Not closed (3)" so they get cleaned up. Where: `StaffAppointments.tsx`.

**H64 — Billing search should understand the screen language** (S)
- Problem: the admin billing search matches `p.status` raw (`AdminBillingPage.tsx:64`), the English database word (`paid`, `pending`). An admin using Arabic types "مدفوع" and gets nothing.
- Who: the platform admin.
- Change: match against the translated label too, `t(statusKey)`, as the badge already shows it. Or replace the free-text status match with the status filter chips the Payments page already uses.

**H65 — "View document" may do nothing on iPad Safari** (S)
- Problem: `AdminBillingPage.tsx:205` calls `window.open` **after** waiting for the signed link. Safari's popup blocker often blocks a new tab that isn't opened directly in the click, with no message.
- Who: the admin, if they work on an iPad.
- Change: open the tab first (`const w = window.open('', '_blank')`), then set `w.location = signedUrl` when the link arrives. Or show the link in a toast to tap. (From reading code; not tried on a device.)

### AA) Voice dictation and AI scribes

Background in plain words: **speech-to-text (STT)** turns recorded speech into text. An **AI scribe** goes further: it listens to the whole consultation and writes a structured note (SOAP = Subjective, Objective, Assessment, Plan, the standard visit-note format). Gulf/Saudi dialect is harder than formal Arabic (MSA): vendors quote about 85–95% accuracy for MSA and admit it drops for dialects. Expect doctors to dictate in a mix of Arabic and English drug names.

| Option | What it does | Price (seen 2026-11-04) | Saudi / Arabic | Effort with React + edge functions | Risk / lock-in |
|---|---|---|---|---|---|
| **Keyboard dictation** (iPadOS / Android Gboard) | The 🎤 on the on-screen keyboard types into any text box | Free | Arabic and English supported by both OSes | **None** (H62 tip) | Audio goes to Apple/Google; no control over quality |
| **ElevenLabs Scribe v2** | Batch and real-time STT, 90+ languages | ~$0.22/hour batch, $0.39/hour real-time (Starter plan, after a price cut from $0.40) | Arabic yes; dialect quality vendor-claimed | **S–M**: record with `MediaRecorder` in the browser, upload to an edge function, which calls the API with a secret key | Audio of the consultation leaves KSA (PDPL: tell the clinic, add to the privacy notice) |
| **OpenAI `gpt-4o-transcribe` / `-mini`** | Batch STT | ~$0.006/min (~$0.36/hour); mini ~$0.003/min | Arabic yes | S–M, same pattern | Same data-transfer point |
| **Whisper large v3 on Groq** | Open-source model, hosted | $0.111/hour (turbo $0.04/hour), Groq's page, Oct 2026 | Arabic yes, weaker on dialect | S–M | Open model: could later run elsewhere, so least lock-in |
| **Saudi vendors (Hams.ai, Emotech)** | Arabic-first STT, dialect focus | Not published (sales) | Built for Saudi/Gulf dialects; may offer in-Kingdom hosting | M (sales process, unknown API) | Small vendors; ask about data residency, which helps PDPL |
| **Vet AI scribes (ScribVet, Coggo, Scribenote, ScribbleVet)** | Listen to the visit, write a SOAP note | Coggo: free 10 notes/month, Pro $99/vet/month; ScribVet $49–97/month (sources disagree); Scribenote $79–99/month | Coggo advertises Arabic + RTL; ScribVet's Arabic claims inconsistent; ScribbleVet was bought by Instinct (a rival practice system) in Jan 2026 | **L**: mostly standalone apps; copy-paste or a partner API | Costs as much per doctor as Touq itself might; clinic data in a US vendor |

For Touq specifically: the session form already has separate boxes (complaint, physical exam, plan, remarks), so plain STT into the focused box gives most of the value. A full AI scribe needs a language model on top, plus a doctor review step. Recording a whole visit also records the owner, which needs their consent (the waiver feature could carry that line).

**Recommendation (AA):** now: H62's tip only (free, no code). At v3: one 🎤 button using a **batch** STT API through an edge function. Start with ElevenLabs Scribe v2 or Groq Whisper, and first test 20 real dictations from a partner vet in Saudi dialect before choosing. Don't keep the audio after transcribing. Skip full AI scribes until clinics ask for them.
