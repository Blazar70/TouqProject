## 3. Bugs (new)

**B17 — Medium — Phone numbers typed with Arabic digits disappear**
- Where: `src/lib/phone.ts:6`. `raw.replace(/\D/g, '')` keeps only the ASCII digits 0-9, so Arabic-Indic digits (٠٥٠١…) are removed. The global Arabic-digit fix (`arabicDigits.ts:19`) only applies to `type="number"` fields, and `PhoneInput` is a text field.
- Scenario: a receptionist on a tablet with the Arabic keyboard types ٠٥٠١٢٣٤٥٦٧ in "Register pet". Nothing appears in the box. The same function powers `phoneKey`, which owner search uses (`owners.ts:8`), so searching an owner by phone in Arabic digits finds no one. The branch phone check (`isValidClinicPhone`) also rejects Arabic digits.
- Fix: in `formatSaudiPhoneInput` (and `isValidClinicPhone`), call `toLatinDigits(raw)` before stripping non-digits. Add one test case to `phone.test.ts`.

**B18 — Medium — The PDPL owner export can be silently incomplete**
- Where: `src/lib/ownerExport.ts:14-25`. Only the `owner_files` query checks `error`. The pets query and the 7 parallel queries ignore theirs, and a failed one becomes an empty list.
- Scenario: the Wi-Fi drops for a moment during a PDPL access request. The manager prints a report that says the owner has "None" for visits and invoices, and hands it over as complete.
- Fix: after `Promise.all`, `for (const r of results) if (r.error) throw r.error`. Do the same for `pets`. `OwnerDetail.tsx` already shows thrown errors.

**B19 — Low — Pasting a phone number cuts it short**
- Where: `src/components/PhoneInput.tsx:35`, `maxLength={9}`. The browser cuts pasted text to 9 characters *before* `formatSaudiPhoneInput` can remove the `0` or `+966`.
- Verified in Chromium: inserting `0501234567` leaves `050123456`. That becomes `50123456` (8 digits) and is shown as invalid. `+966 50 123 4567` becomes `+966 50 1`.
- Scenario: a receptionist copies the owner's number from WhatsApp and pastes it. The field shows an error, and they have to retype it.
- Fix: remove `maxLength`. The formatter already caps the number at 9 digits (`phone.ts:8`).

**B20 — Low — Wrong number words in Arabic (and one in English)**
- Where: `LanguageContext.tsx:37`. `t()` only knows "1" versus "everything else". Arabic has six plural forms: zero, one, two, few (3-10), many (11-99) and other. Most Arabic strings use the singular noun, which is only correct for 11 and up.
- Examples:
  - The vaccine schedule shows "كل 7 يوم" (should be "كل 7 أيام") (`VaccinationPanel.tsx:180`).
  - "الحفظ ينقل 3 موعد" (should be "3 مواعيد").
  - "Recounted 1 times" / "أُعيد العدّ 1 مرات" (`CashCountPanel.tsx:111`, no `_one` variant in either language).
- 48 Arabic strings use `{count}`.
- Fix (S): `const cat = new Intl.PluralRules(language).select(Number(vars.count))`, try `${key}_${cat}` first, then the plain key. Then add `_two`, `_few` and `_many` Arabic variants for the strings that show often. `Intl.PluralRules` is built into every browser, so no new library is needed.

**B21 — Low — The platform admin can't use "Delete owner data"**
- Where: `0089_owner_anonymise.sql:22`. The function allows admins (`:19`), but then looks up the owner with `clinic_id = current_user_clinic_id()`. That helper only returns a clinic for `role = 'vet'` (`0031:19-22`), so for an admin it returns null and the call always fails with "Owner not found".
- Scenario: a clinic asks the platform admin to handle a deletion request. It can't be done without signing in as a manager.
- Fix: `and (current_user_is_admin() or clinic_id = current_user_clinic_id())`. Or remove the admin branch if only managers should do it.

## 4. Security (new)

**S14 — Medium — A branch manager can take over staff who also work at other branches**
- Where: `supabase/functions/_shared/staffRules.ts:57`. For every action except `set_branches`, a target counts as "in scope" if they share **one** branch with the manager (`some(inScope)`). That includes `reset_password`, `set_role` and `set_disabled`.
- Scenario: Manager M runs branch A only. Nurse N works at A and B. M resets N's password, signs in as N, and can now book, write records and sign waivers at branch B. `enforce_branch_write` would block M there. Or M changes N to receptionist, which gives N money access at B.
- Fix: keep `some()` for `update_staff` (name and phone edits), and use `every(inScope)` for `reset_password`, `set_role` and `set_disabled`. Add a case to `staffRules.test.ts`.

**S15 — Low — Any staff member can change which service is the "hospital night"**
- Where: `0037_service_payments.sql:61`. The `services_all_vet` policy gives every staff member in the clinic full access. Only the UI limits the `hospital_night` switch to managers (`SettingsPage.tsx:629`).
- Note: editing the price list is open to all staff on purpose (0074). Only this flag is the issue.
- Scenario: a receptionist uses the API to move the flag to a cheaper service. After that, "Bill this stay" prices every night at the wrong rate.
- Fix: a `before update` trigger that raises an error when `hospital_night` changes and the caller is not a manager.

**S16 — Low — Owner export includes the previous owner's data**
- Where: `ownerExport.ts:14-24`. It collects every waiver and invoice of the owner's *current* pets, including those from before the pet changed owner (pet move, or merge in 0064).
- Scenario: Bella moves from owner A to owner B. B asks for a PDPL export and gets A's signed waivers, including A's `signer_name`, and A's invoices.
- Also: invoices of purged pets (`pet_id` set to null, 0069) are missing from the owner's export.
- Fix: leave out `signer_name` when it isn't this owner, or limit waivers and invoices to the dates since the pet joined this owner.

**S17 — Low — `notify-status-change` reveals a bit too much**

- Fix: return only `{ sent: n }`, and move the caller check above the lookup.

## 6. HCI / visual / usability ideas

**H26 — Start in Arabic on an Arabic device** (S)
- Problem: `getInitialLanguage` (`LanguageContext.tsx:18-21`) returns English unless the user saved "ar" earlier. On a brand-new clinic tablet set to Arabic, the first screen (login) is in English.
- Who: every new staff member, most of whom read Arabic first.
- Change: `return stored === 'ar' || (!stored && navigator.language.startsWith('ar')) ? 'ar' : 'en'`. Also wrap `localStorage` in `try`, because it throws in some private-browsing modes and the whole app would fail to start.

**H27 — Phone field: say why it is wrong, and suggest the right keyboard** (S, do it with B17/B19)
- Problem: the error `<p className="field-error">` (`PhoneInput.tsx:42`) is not linked to the input. A screen reader only hears "invalid", with no reason, and the message isn't announced. The field also has no `autoComplete`, so the browser can't offer saved numbers.
- Who: staff using screen readers or keyboards, and receptionists retyping numbers.
- Change: give the error an `id` (`useId()`), set `aria-describedby` on the input, and add `role="alert"` (as `FormError` does). Add `type="tel"` and `autoComplete="tel-national"`, and keep `inputMode="numeric"`.

**H28 — Proper Arabic number words** (S, see B20)
- Problem: Arabic readers see grammar mistakes on everyday screens (vaccine schedule, trash countdown, time-off warnings). It makes the product look machine-translated.
- Who: every Arabic user, and especially clinic managers judging the product during a pilot.
- Change: add `Intl.PluralRules` to `t()`, then add `_two`/`_few` variants for about 10 high-traffic strings first (`vaccination.everyDays`, `trash.daysUntilPurge`, `timeOff.willMove`, `timeOff.savedMoved`, `dashboard.overdueCount`, `reports.recounted`). Optionally, a "one" form with the number word after it (موعد واحد) reads more naturally than "1 موعد".

**H29 — A small test that keeps the two languages in sync** (S)
- Problem: `translations.ar` isn't type-checked against `translations.en`. A missing Arabic key quietly falls back to English (`LanguageContext.tsx:38`). They match today (1,131 = 1,131), but nothing stops that changing.
- Who: Arabic users, the first time a new feature ships with English text left in.
- Change: one vitest test that compares the key sets and the `{placeholders}` (allowing `_one` strings to differ). Or type `ar` as `Record<TranslationKey, string>`.

### K) Translation tooling (EN/AR strings)

What Touq has today: a home-made `t()` with one 146 KB `translations.ts` holding 1,131 keys in each language. Both languages are bundled into the main JS. It works, it is type-safe for English keys, and it has no dependencies. What it lacks: Arabic plurals (B20), a parity check (H29), and a way for a non-developer (for example an Arabic reviewer) to fix wording.

| Option | What it is | Price (seen 2026-10-27, unverified) | Effort | Risk / lock-in |
|---|---|---|---|---|
| Keep it home-made + `Intl.PluralRules` | Built into the browser; returns zero/one/two/few/many/other for Arabic | Free | S (about 5 lines) | None |
| i18next + react-i18next | The standard React translation library, with Arabic plurals built in (`_two`, `_few`, …) | Free | M: about 1,100 call sites stay `t('key')`, but the provider and types change | Low; an extra ~40 KB of JS |
| Tolgee (open source) | A web editor where translators click text in the running app and edit it | Cloud free: 500 keys / 3 seats (vendor) **or** 1,000 strings (directories). Team about €42/month, Business about €125/month. Free self-hosted up to 10 seats | M | **Touq already has 1,131 keys, above the free cloud limit** |
| Crowdin | A big translation-management platform | Free: 60k "hosted words" (words × languages), 1 private project. Pro about $50–59/month | M (GitHub sync) | Free-plan translations go into Crowdin's shared translation memory, a privacy concern for unreleased features |
| Weblate | Open-source platform, Git-based | Libre plan free only for **public** open-source projects. Hosted from about €47/month for 10k strings | M | Touq is private, so it's self-host or pay |

Why it matters for Touq: Arabic is the main language for most users. Grammar slips (B20) and leftover English strings hurt trust more than missing features do. You are the only translator now, so a platform's value is low until a native-speaker reviewer joins.

**Recommendation (K):** don't add a service yet. Do B20 + H29 (built-in `Intl.PluralRules` and one test), which costs nothing. Revisit **Tolgee self-hosted** (or a paid plan) only when an Arabic copy editor joins. Its click-to-edit-in-the-app works well for RTL review. Moving to i18next isn't worth it now, because once plurals are added the home-made `t()` covers what Touq needs.

### L) Online booking for pet owners

The need: owners book or request a slot from a link (website, Instagram bio, WhatsApp reminder) without calling. In KSA a lot of booking happens by WhatsApp chat, so "send a booking link in the reminder" fits how people already book.

| Build it in Touq: a public "request a slot" page + edge function | The owner picks a service and day, sees free slots (Touq already has `appointmentConflicts.ts`), and submits name + phone. No public RLS: write only through an edge function using the service role and strict validation |
| Cloudflare Turnstile (anti-bot check) | A free, privacy-friendly CAPTCHA. | Vetstoria | Vet-specific booking widget that syncs live with ~30 practice systems | About £199–299/month (UK site) / $249/month (Capterra) / €149 per location (FitGap) | No KSA presence found; Arabic unknown | L: it only integrates with PMSs it partners with, and Touq isn't one | Expensive, and a vendor decides the integration |
| Cal.com | Open-source scheduling. Cloud Teams about $12–15/seat/month; Platform API about $0.99/booking above 25/month; self-host free | Arabic/RTL not confirmed | M (webhooks into an edge function) | Two calendars to keep in sync, and double-booking risk |

Why it matters for Touq: the receptionist's phone time is the clinic's biggest hidden cost, and missed calls are lost bookings. Owner reminders (0085) already send a WhatsApp link, and a "book your next visit" link there closes the loop.

**Recommendation (L):** build the small in-house version after the pilot starts. It should be **"request a slot", not instant booking**: reception confirms each request, so there is no double-booking or abuse. Use one edge function (validate phone with `isValidSaudiMobile`, rate-limit per phone, Turnstile token checked on the server) that inserts a `requested` appointment. Skip Vetstoria and Cal.com, which cost more than they save and don't know Touq's branches, doctors or time off. Effort: M (a new status value + 1 page + 1 function + RLS-free writes through the function).
