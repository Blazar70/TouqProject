**B35 — Low — The unit tests crash on any machine without a `.env` file**
- Where: `src/lib/imageUpload.test.ts` imports `./imageUpload`, which imports `./supabase` at the top. `src/lib/supabase.ts:8` throws when the two settings are missing.

The test itself checks only `fitWithin` and `validateImageFile`, two pure functions (functions that only compute a result from their inputs) that never touch Supabase.
- Fix (S): add `vi.mock('./supabase', () => ({ supabase: {} }))` at the top of the test, or move the two pure functions into a file that doesn't import Supabase.

**B36 — Low — A photo that can't be shrunk is accepted at pick time, then lost at save (or uploaded at full size)**
- Where: `src/lib/imageUpload.ts:15-18`. `validateImageFile` now allows JPEG/PNG/WebP/HEIC up to **30 MB**, on the assumption that `shrinkImage` will bring them under 5 MB. But `shrinkImage` (`:29-48`) quietly returns the **original** file when the browser can't decode it. HEIC can't be decoded in Chrome, Edge or Firefox, and that path is in the code comment.
  - `SessionPage.tsx:246-255` and `RegisterPetPage.tsx:149`: `uploadPhoto` then returns `tooLarge`, the user sees only "Could not save photo", and `setPhotoFile(null)` throws the photo away. Before this change, the photo was refused straight away with "too large", so the user knew to pick another.
  - `InpatientPanel.tsx:163-165`: there is no size check after shrinking, so the original file (up to the bucket's 30 MB limit, 0081) goes up as it is, and a HEIC can't be shown in Chrome anyway.
- Scenario: a nurse on a Samsung tablet (Samsung phones can save HEIC) attaches a 12 MB HEIC to a visit. The preview may be blank, they press Save, the record saves, and the photo silently doesn't.
- Fix (S): run `shrinkImage` when the file is picked (in each `handle…File` function), then run `validateImageFile(shrunk, false)` on the result. The user gets the "too large / not supported" message before saving, and the inpatient screen gets the same 5 MB rule.

### W) Stock, expiry dates and scanning medicine barcodes

**How medicine boxes are labelled in KSA.** Saudi drug boxes carry a **GS1 DataMatrix**, a small square 2D barcode. It holds the product code (GTIN, the AI `(01)`), serial number `(21)`, expiry date `(17)` and batch/lot `(10)`, as required by the SFDA (Saudi Food and Drug Authority) track-and-trace system **RSD**. One scan can therefore fill the product, batch and expiry date. Whether veterinary-only products fall under RSD is **unclear**: one source says it covers human registered drugs, while a vendor guide lists veterinary products. Many vet products sold in KSA are imported human-style packs that carry the code anyway.

| Option | What it is | Price (seen 2026-11-02) | Fit for Touq | Effort | Risk |
|---|---|---|---|---|---|
| **USB/Bluetooth 2D handheld scanner ("keyboard mode")** | The scanner types the code into whichever field has focus, then presses Enter, just like the microchip readers Touq already handles (B31 fix) | Hardware only, about $30–80 per unit (typical retail) | Works on Windows, Android and iPad (Bluetooth), with no new code for reading. Touq just needs a GS1 parser (about 30 lines, plus a test) | **S** | In keyboard mode, many scanners **drop or garble the GS separator (ASCII 29)** between variable-length fields, so batch and serial run together. | **Camera scanning, `zxing-wasm`** (zxing-cpp compiled to WebAssembly, fast compiled code that runs in the browser) | An open-source decoder that works in every modern browser, including iOS Safari, and reads DataMatrix with GS1 support | Free, **MIT** licence (zxing-cpp Apache-2.0) | Load it lazily (only when the scanner opens), about **1 MB** for the reader-only build, so the main bundle stays the same. **What a minimal stock feature in Touq would look like (for v3 planning, not now):**
- One `stock_batches` table (`clinic_id`, `branch_id`, `service_id`, `batch`, `expires_on`, `qty`) with the same clinic RLS as `services`. Sold quantities come off by FEFO when an invoice line is added, through the existing invoice DB functions (0061). Add a "Expiring in 30 days" list on the dashboard.
- Receiving stock: focus a "Scan box" field, parse the GS1 string, and fill batch and expiry automatically.

**Recommendation (W):** don't build stock before v3. When you do, start with **keyboard-mode handheld scanners plus a small GS1 parser** (cheapest, works on iPad, and reuses the scanner-Enter handling already in `PetPicker`). Add `zxing-wasm` camera scanning only if clinics ask for phone scanning. Skip Dynamsoft. Before promising "scan the SFDA code", email the RSD team (tracking.drug@sfda.gov.sa) to ask whether vet products are in scope.

### X) MEWA rules for vet records (not settled)

An English search found only a 2019 MEWA news item: MEWA penalised 20 vet facilities under the **GCC law on practising veterinary medicine**, and vet-product cases go to the SFDA under the **GCC Law of Veterinary Products**. It found no Saudi rule on **how long visit records must be kept** or on a **controlled-drug register**. Other countries' rules (3+ years in several Australian states, for example) must not be assumed. **Recommendation:** before v3, ask a partner clinic's licensed vet, or MEWA directly, for the Arabic regulation text. Its answer decides Touq's record-retention period and whether purging after 7 days in the trash is allowed for medical records. Next time, search in Arabic (نظام مزاولة مهنة الطب البيطري).
